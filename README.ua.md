## 📝 Завдання

Потрібно продовжити створення застосунку для роботи з колекцією контактів.

Необхідно додати:

- пагінацію;
- сортування за ім’ям;
- фільтрацію контактів;
- валідацію вхідних даних.

---

## ✅ Критерії прийому

- Завдання виконано у гілці **`hw4-validation`**.
- При здачі домашньої роботи є:
  - посилання на репозиторій з вихідним кодом на GitHub;
  - посилання на задеплоєний проєкт на [**render.com**](https://render.com/) (гілка `hw4-validation`).
- Під час виконання коду завдання відсутні помилки.
- Дотримано файлової структури застосунку, яка наведена в матеріалах курсу.

## 🪜 Покрокове виконання завдання

---

### Крок 1

Створіть гілку **`hw4-validation`** з гілки **`hw3-crud`**  
і виконуйте це завдання саме в гілці `hw4-validation`.

---

### Крок 2

Покращіть обробку вхідних даних (валідацію) у вашому застосунку.

Для цього:

- створіть функцію `validateBody`, яка:
  - приймає схему валідації;
  - повертає middleware для валідації `body` запиту;
- додайте валідацію для маршрутів:
  - `POST /contacts`
  - `PATCH /contacts/:contactId`
- побудуйте схеми валідації, базуючись на описі властивостей вашої MongoDB-моделі;
- для всіх полів типу `string` додайте обмеження:
  - мінімальна довжина — **3 символи**;
  - максимальна довжина — **20 символів**;
- додайте middleware `isValidId` для перевірки валідності `id` та використайте його в усіх маршрутах, які працюють з `id`.

---

### Крок 3

Додайте пагінацію до маршруту:

GET /contacts

Використовуйте такі query-параметри:

- `page` — номер сторінки (за замовчуванням `1`);
- `perPage` — кількість елементів на сторінці (за замовчуванням `10`).

---

### 📦 Вимоги до відповіді сервера

У властивості `data` відповідь сервера повинна містити:

- `data` — масив контактів з поточної сторінки;
- `page` — номер поточної сторінки;
- `perPage` — кількість елементів на сторінці;
- `totalItems` — загальна кількість контактів у колекції;
- `totalPages` — загальна кількість сторінок;
- `hasPreviousPage` — чи існує попередня сторінка;
- `hasNextPage` — чи існує наступна сторінка.

---

### 📄 Формат відповіді сервера

```json
{
  "status": 200,
  "message": "Successfully found contacts!",
  "data": {
    "data": [
      /* contacts */
    ],
    "page": 2,
    "perPage": 4,
    "totalItems": 6,
    "totalPages": 2,
    "hasPreviousPage": true,
    "hasNextPage": false
  }
}
```

### Крок 4

Додайте можливість задавати порядок сортування контактів за іменем у відповіді для маршруту: GET /contacts

Для цього використовуйте такі query-параметри:

- `sortBy` — визначає, за якою властивістю потрібно виконувати сортування;
- `sortOrder` — визначає порядок сортування:
- `asc` — висхідний порядок (значення за замовчуванням);
- `desc` — низхідний порядок.

---

### Крок 5 (необов’язковий)

За бажанням додайте можливість фільтрації контактів у відповіді для маршруту: GET /contacts

за такими параметрами:

- `type` — відображає тип контакту (значення властивості `contactType`);
- `isFavourite` — вказує, чи є контакт обраним.
